Phase 2 · Critical Bug Fix
OS Data Bottleneck — Root Cause & Fix
download_tcga.py src/preprocess.py

Initial survival modeling used only 905 of 7,902 samples (11.4%) due to a data collection bug — not missing data. Full diagnosis and resolution below.

The Three-Layer Problem

LayerRoot CauseEffect
Bug: GDC API pagination Offset incremented by row count (~9,428 expanded rows) instead of case count (2,000 patients). Second request at from=9428 found no additional cases. Only 2,000 of 11,160 TCGA patients fetched
Consequence: 5 cancer types GDC's default sort order surfaced BRCA, OV, COAD, LUSC, SKCM first. Remaining 28 cancer types had zero survival records. 28 of 31 cancer types in cohort: no OS data
Join amplification Multi-modal intersection produced 7,902 samples spanning all 31 types; almost all from the uncovered 28 types had no survival match. 905 samples → survival-annotated cohort

FT-Transformer: Feature Tokenizer Detail

Each of the 50 input features gets its own learned linear projection: tokenj = Wj · xj + bj where Wj, bj ∈ ℝ64. A CLS token is prepended. After L=2 pre-norm transformer blocks (MultiheadAttention + GELU FFN), the CLS token is projected to a scalar log-risk score.

⚠ Gotchas & Fixes
LightGBM 4.x removed built-in 'cox' objective LightGBMError: Unknown objective type name: cox
✓ Fix: Implemented custom Cox objective from scratch. LGB 4.x API: pass objective=callable in params dict (not fobj= kwarg). Function signature changed to f(preds, dataset) where labels are retrieved via dataset.get_label(). Gradient derived from Breslow approximation with diagonal Hessian.
TabPFN excluded — not suitable for this task
TabPFN is designed for ≤1,000 samples + classification only. With 7,787 samples and a survival (time-to-event) objective, it cannot be applied without heavy degradation. Replaced with LightGBM which properly handles censoring.
XGBoost survival label convention
✓ Label encoding: label = OS_time if OS_event==1 else -OS_time (positive = event, negative = censored). This is XGBoost's required format for survival:cox and was replicated for the custom LightGBM objective.

Critical Insights

1. The survival bottleneck was an engineering bug, not biology. The GDC API pagination error that reduced 7,902 to 905 samples was entirely fixable. Switching to TCGA-CDR gave 7,787 samples and 2,170 events — a 9× increase in statistical signal that fundamentally changed what models could learn.
2. MOFA+ as feature engineering outperforms raw PCA. MOFA+ compressed 2,300 cross-modal features into 18 biologically structured factors, raised mean C-index from 0.724 to 0.751, and reduced fold-to-fold variance 7× (std 0.053 → 0.008). The key gain is not raw performance but reliability — MOFA+ factors capture coordinated multi-omics signals that individual PCA projections miss.
3. FT-Transformer beats GBDT but the gap is small. At 0.751 vs 0.747/0.745, the transformer's attention mechanism captures interaction terms between cancer type dummies and MOFA factors that gradient boosted trees partially miss. The gap would likely grow with larger sample sizes or finer feature resolution.
4. Age dominates all molecular signals (SHAP=0.40 vs 0.28 for best MOFA factor). Pan-cancer survival models should always include age and be fit on cancer-type-stratified subsets rather than across all types simultaneously. The SHAP signal from age likely partially captures cancer-type effects (older patients disproportionately have prostate, CRC) that the cancer type dummies don't fully absorb.
5. MOFA Factor8 is the priority molecular signal to decode. It ranks 2nd in SHAP importance (avg=0.283) and is the most consistent signal across all three model architectures (CV = 0.003 across models). Its gene loadings in mofa_weights_expression.csv and mofa_weights_cnv.csv should be extracted and subjected to pathway enrichment analysis.
