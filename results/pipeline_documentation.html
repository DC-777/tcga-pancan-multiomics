Key Finding
Cancer histological type is the dominant axis of variation in expression space. Brain tumors, breast, and kidney cancers form tight, well-separated clusters on the UMAP. Thyroid and prostate are tightly packed (low intra-type heterogeneity). The 905 survival-annotated samples are broadly distributed across the manifold — no obvious survival-enriched region — making pan-cancer survival modeling an inherently noisy task.

Loss Function
Breslow approximation of Cox partial log-likelihood
L = −(1/|D|) · Σ_{i∈D} [θ_i − log Σ_{j: T_j ≥ T_i} exp(θ_j)]
Where D = set of uncensored (event) samples, θ = model risk score. Sort by descending time, then apply logcumsumexp for efficiency.

Phase 6 · SHAP Feature Interpretation

Quantify per-sample feature contributions using model-appropriate SHAP methods

📄 src/supervised/shap_analysis.py

Cox Ridge — Exact Linear SHAP

SHAP_i(x) = β_i × (x_i − Ē[x_i])

Linear models have exact, closed-form SHAP values — no sampling required. Since features are StandardScaled, Ē[x_i] ≈ 0 and SHAP reduces to β_i × x_i per sample. This is equivalent to LinearExplainer output.

DeepSurv — GradientExplainer

shap.GradientExplainer(model_2d, background[100])

Back-propagates expected gradients through the network. Background = 100-sample random subsample as the reference distribution. Wrapper class _DeepSurv2D added to keep output 2D (n, 1) as required by the explainer.

⚠️ Gotchas & Fixes (3 issues) ▼
AttributeError: ndarray has no attribute 'ptp'Replace with .max() - .min()
numpy.ndarray.ptp() was removed in NumPy 2.x. Used for normalising feature values to 0–1 for colour mapping in the beeswarm plot. Fix: (arr - arr.min()) / (arr.max() - arr.min() + 1e-9).
IndexError: too many indices (shap shape (905, 80, 1))_DeepSurv2D wrapper + squeeze(-1)
GradientExplainer requires 2D model output (n, 1), but our model squeezes to 1D (n,). Fix: added wrapper class _DeepSurv2D(nn.Module) that calls out.unsqueeze(1). SHAP returns shape (905, 80, 1) — squeezed back to (905, 80) after extraction.
TypeError: only integer scalar arrays can be converted to scalar indexConvert numpy array to list before indexing Python list
np.argsort() returns a numpy array; indexing a Python list with a numpy array raises TypeError. Fix: order = list(np.argsort(...)) before using it as an index into feature_names.

⚠️ Gotchas & Fixes (4 issues) ▼
AssertionError: Duplicated entries in data (long-format DF)Switch to matrix API
Initial approach built a 35.5M-row long-format DataFrame (sample × view × feature × value). Duplicate gene names (from HGNC symbol mapping) caused the assertion to fail. Fix: switched to set_data_matrix() with data[view][group] numpy arrays — far more efficient and bypasses the deduplication check.
AssertionError: Length of views_names != number of viewsCorrect API: data[view][group] not data[group][view]
mofapy2 matrix API nests data as data[view_idx][group_idx], not data[group_idx][view_idx] as initially assumed. M = len(data) = number of views. Transposing the nesting fixed the shape mismatch.
AssertionError: Duplicated entries in features_names (across views)Prefix feature names per view (E_/M_/C_)
mofapy2 requires globally unique feature names across ALL views. The same gene can appear in expression and CNV views — naming collisions cause the assertion. Fix: prefixed all feature names with view abbreviation: E_GENE, M_GENE, C_GENE.
AttributeError: 'ndarray' has no attribute 'values' (extract_results)Handle ndarray + dict + list return types
model.nodes["Z"].getExpectation() returns a plain ndarray (not a dict) in mofapy2 0.7.4. Extract function now checks isinstance(Z_raw, dict) → isinstance(Z_raw, list) → else uses the array directly. Same pattern for weights.
